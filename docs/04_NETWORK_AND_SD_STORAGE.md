# 04. Сетевая Синхронизация (`script.google.com`) и Структура MicroSD

## 1. Архитектура Шаринга Данных через Google (Без Блокировок в РФ)

### Почему связка Google Apps Script + Google Drive работает на 100%
1. Домен `script.google.com` и домен выдачи ответов `script.googleusercontent.com` **не блокируются в РФ** и работают напрямую без VPN.
2. **Решение проблемы лимитов записи Google Диска:** 
   Если 10 гаджетов начнут физически перезаписывать файлы на Google Диске каждые 5 секунд, Google Drive API заблокирует папку по квоте уже через 15 минут. 
   **Как мы это решаем внутри скрипта:** 
   В Google Apps Script есть встроенный сверхбыстрый оперативный кэш — `CacheService` (хранит данные в RAM на серверах Google, чтение и запись занимают $< 40\text{ ms}$, лимиты — десятки тысяч операций). 
   * Каждые **5–10 секунд** гаджеты обмениваются данными через `CacheService` скрипта (мгновенно и без расхода квот Диска).
   * А **раз в 1 минуту** этот же скрипт автоматически сохраняет сводный дамп `network_dump.json` в физическую папку Google Диска!


## 2. Как Устроена Сеть и Роль Админа

1. **Создание сети:** Админ сети создает у себя на Google Диске папку (например, `CyberWeather_Net_Alpha`), открывает к ней файл Google Apps Script (вставляет готовый код из нашего репозитория на 80 строк) и нажимает **Deploy as Web App** (`Execute as: Me`, `Who has access: Anyone`).
2. **Подключение участников:** Админ скидывает друзьям полученную ссылку вида `https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec` (или просто короткий `DEPLOYMENT_ID`).
3. **Мультисетевой режим:** У каждого пользователя в файле `/config.json` на флешке есть массив `networks` со списком таких ID. При синхронизации гаджет отправляет один JSON-запрос, который обновляет его статус во всех прописанных сетях и возвращает объединенный список всех уникальных соседних гаджетов из этих папок.

### Проксирование Космоса (`CelesTrak` и `NOAA`) для Устройств из РФ
Поскольку сайт `celestrak.org` закрыт жестким фильтром Cloudflare для российских IP:
* **Механизм 1 (Автоматический на стороне Google):** В том же скрипте на `script.google.com` настраивается стандартный минутный/часовой триггер Google. Так как серверы Google находятся в США, скрипт сам раз в 6 часов свободно скачивает свежие орбиты спутников (`TLE`) с CelesTrak и сводку космопогоды с `NOAA SWPC` и кладет их в файл `space_global.json` внутри папки сети на Google Диске!
* **Механизм 2 (Резервный через Админский гаджет):** Поскольку админское устройство находится вне РФ, оно может само скачивать `CelesTrak`/`NOAA` и пушить их в общую папку при синхронизации.
* **Результат:** Любой гаджет в РФ просто забирает готовый `space_global.json` через `script.google.com` с гарантированной 100% доступностью.


## 3. Техническая Особенность Запросов с ESP32-S3 к `script.google.com`

При обращении к `script.google.com` сервер Google всегда отвечает кодом `HTTP 302 Moved Temporarily` и перенаправляет клиент на одноразовый URL `https://script.googleusercontent.com/macros/echo?...`.
В коде прошивки на ESP32-S3 это решается двумя стандартными строками в `HTTPClient`:

```cpp
WiFiClientSecure client;
client.setInsecure(); // Пропуск проверки корневого сертификата для экономии RAM и скорости
HTTPClient https;
https.setFollowRedirects(HTTPC_FORCE_FOLLOW_REDIRECTS); // Обязательное следование за 302 редиректом Google!
https.setTimeout(4000);
```


## 4. Структура Файлов на MicroSD-Карте (Ручная Подготовка и Кэш)

Перед первым включением гаджета пользователь вставляет MicroSD-карту в компьютер и закидывает на нее базовый пакет файлов («Zero-Day Pack»). Эти статические данные **никогда не перекачиваются по сети**, экономя трафик и ускоряя старт до 1 секунды.

```
SD_CARD_ROOT/
├── config.json                 <-- Ручной конфиг пользователя (Wi-Fi, имя, координаты, сети)
├── maps/                       <-- Векторные карты 100x100 км (берега, реки, дороги, высоты)
│   ├── local_map.vec           <-- Карта своей локации (скачивается на ПК генератором из репо)
│   ├── NODE_ALEX.vec           <-- Кэш карты соседа (сохраняется один раз при знакомстве с узлом)
│   └── NODE_MAX.vec
└── cache/                      <-- Автоматический кэш для мгновенного восстановления после ребута
    ├── space_global.json       <-- Орбиты TLE 25 спутников + последняя сводка NOAA (живет 24ч)
    ├── weather_grid.json       <-- Последний скачанный прогноз Open-Meteo (живет 1ч)
    ├── peers_list.json         <-- Список известных соседних устройств и их координат
    └── pager_chat.json         <-- Последнее входящее "Сообщение дня" и метка времени своей отправки
```

```json

  "device_name": "ALMATY_HQ",
  "is_admin_node": true,
  "wifi": {
    "ssid": "MyHomeWiFi",
    "password": "SecretPassword123"
  },
  "location": {
    "lat": 43.2389,
    "lon": 76.8897,
    "alt_m": 780,
    "timezone_utc_offset": 5

    "local_refresh_sec": 1,

```
